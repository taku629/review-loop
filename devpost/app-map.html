Review Loop — App Map

Snapshot of commit 7361094+ (may drift as the code changes).

What it is

A browser-only spaced-repetition coach for competitive programmers. Four views (Today, Library, Import, Settings) and a problem drawer read and write one reducer-backed state saved in localStorage. Importers call the public AtCoder Problems and Codeforces APIs; an optional Vite middleware proxies AI hints when OPENAI_API_KEY is set.

One action: rating a review

Reference route (not toured interactively)

  1. src/components/ReviewRow.tsx — the rating buttons show previewIntervals(problem.card) and call onRate; TodayView.tsx rate() dispatches and shows the toast.
  2. src/lib/store.ts — reducer, case 'review': updates the card, appends history and the review log; usePersistentStore writes to review-loop/v1.
  3. src/lib/srs.ts — review(), nextInterval(), nextEase(): the SM-2-style maths, covered by tests/srs.test.ts.

To change this, start here

  • Intervals / ease: src/lib/srs.ts (then run npm test).
  • What counts as a struggle: src/lib/importers/struggles.ts detectStruggles.
  • New judge URL format: src/lib/urlParse.ts parseProblemUrl + Judge in types.ts.
  • Hint prompts: server/hintPlugin.ts LEVELS.
  • Look and feel: CSS variables at the top of src/styles.css.

A practice to reuse

Verify external APIs from the real runtime, not only with curl. The AtCoder metadata looked CORS-enabled with curl but was blocked in Chrome; the browser run during slice 2 caught it, and the fix (build-time snapshot + fallbacks in importers/atcoder.ts loadMeta) is recorded in spec.md → Build-time Notes. On any project that calls third-party APIs from a browser, make one in-browser call part of the first slice's verification.
